## MM-021 | XSS payload in first name field renders in order summary

**Severity:** High
**Priority:** Critical
**Status:** Open

**Summary:** When a script tag is entered in the first name field during checkout, it is reflected in the order summary on step two without proper sanitization. Although not executed in this environment, the lack of output encoding is a security concern.

**Steps to Reproduce:**
1. Add item to cart and proceed to checkout
2. Enter `<b>Test</b>` in the first name field
3. Enter valid last name and postal code
4. Click Continue

**Expected Result:** Input rendered as plain text — `<b>Test</b>`.
**Actual Result:** Input rendered as bold HTML — **Test** — indicating lack of output encoding.

## MM-032 | Finish button double-click submits checkout twice (race condition)

**Severity:** High
**Priority:** Critical
**Status:** Open

**Summary:** Rapidly double-clicking the "Finish" button on checkout step two can trigger two form submission events before the page navigates to the confirmation page. In a real payment system this could cause duplicate charges.

**Steps to Reproduce:**
1. Complete checkout up to step two
2. Double-click the "Finish" button as fast as possible
3. Monitor network requests in DevTools

**Expected Result:** Button disabled after first click; single submission only.
**Actual Result:** Two submission events fired in quick succession.

**Severity Note:** Although not directly harmful in this test environment, this pattern would be critical in a real payment gateway integration.

## MM-040 | Checkout form allows submission via Enter key without filling fields
